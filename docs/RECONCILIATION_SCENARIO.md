# Сценарий сверки с бухгалтером и кассиром (ТЗ §12)

> Цель: на **реальных обезличенных** документах одного периода показать, что остатки, долги и балансы касс в
> BuildFlow совпадают с учётом бухгалтера и кассира, а частичные оплаты, сторно и акты работают как в жизни.
> Где: staging. Длительность: 2–3 часа. Участники: материальный бухгалтер, кассир, управляющий (акты), ведущий.

## 1. Подготовка (за 2–3 дня)
1. **Период и объект.** Один объект, 2–4 недели закрытого периода. Дата начала = дата ввода остатков.
2. **Документы** (копии, не оригиналы): заявки, накладные поставщиков, акты приёмки склада, выдачи и возвраты,
   приходные и расходные кассовые ордера, акты выполненных работ бригад, ведомость остатков склада и касс на начало
   и на конец периода, ведомость долгов поставщикам и бригадам на начало и конец.
3. **Обезличивание:** ФИО → «Сотрудник 1…», поставщики → «Поставщик А…», бригады → «Бригада 1…»; телефоны, ИНН,
   номера паспортов убрать; **суммы и количества оставить** — их и сверяем. Таблица соответствий остаётся у бухгалтера.
4. **Справочники** — импорт из Excel (материалы, поставщики, бригады) — «Справочники → Импорт из Excel».
5. **Учётные записи** — по одной на роль (бухгалтер, кассир, склад, прораб, управляющий), второй фактор подключён.
6. **Контрольные цифры** (заполняет бухгалтер до встречи):

| Показатель | На начало (учёт) | На конец (учёт) | BuildFlow на конец | Совпало |
|---|---|---|---|---|
| Остаток материала X (по 5–10 ключевым) | | | | |
| Долг поставщику А, Б, … | | | | |
| Долг бригаде 1, 2, … | | | | |
| Баланс каждой кассы / счёта | | | | |

## 2. Шаги (вносим документы периода в хронологическом порядке)
1. **Ввод остатков на дату начала** (бухгалтер): склад, кассы, долги → «Провести». Сверка с ведомостью «на начало».
2. **Закупка** (бухгалтер → склад → бухгалтер): заявка → «Выдать в работу» → приёмка складом с фактическими
   количествами (где были расхождения — так и вносим) → накладная → «Подтвердить».
3. **Выдачи и возвраты** (склад): по объекту, блоку, этажу, бригаде.
4. **Касса** (кассир): приходы; оплаты долгов **частями**, как было; прочие расходы — через счёт на оплату и
   согласование бухгалтера.
5. **Ошибочный платёж**: одну оплату кассир сторнирует (запрос → согласование бухгалтера) и проводит заново.
   Отчёт «Сторно за период» — видно, кто инициировал и кто согласовал.
6. **Акты бригад** (прораб → управляющий → кассир): тарифы управляющего → акты → «Утвердить» → оплата частями.
   Один акт отклонить и «Создать на основе».
7. **Повтор**: дважды нажать «Провести» на одном документе / обновить страницу при плохой связи — дублей нет.

## 3. Сверка
1. **Отчёты** BuildFlow на конец периода (Excel): «Остатки», «Долги поставщикам и бригадам», «Балансы и движение касс»,
   «Акты работ» → заполнить колонку «BuildFlow на конец».
2. **Внутренняя сверка системы** (ведущий): `scripts/backup/sql/reconcile.sql` на staging — все проверки 0
   (остатки = Σ движений, балансы = Σ операций, оплачено = Σ распределений).
3. **Расхождения** — в протокол: показатель, учёт, BuildFlow, разница, причина (ошибка ввода / особенность учёта /
   ошибка системы), что делаем. Ошибки ввода исправляем сторно/корректировкой и сверяем снова.

## 5. Сверка пройдена, если
- все контрольные цифры совпали либо каждое расхождение объяснено и не является ошибкой системы;
- внутренняя сверка BuildFlow — 0 расхождений;
- частичные оплаты, сторно через бухгалтера, отклонение и утверждение актов отработали как в жизни;
- повторные нажатия не создали дублей;
- бухгалтер и кассир подтвердили результат (подписи, дата).

Итог сверки и ответы на `docs/PILOT_QUESTIONS.md` → утверждение ТЗ 1.0.
